# 三星回单核验台

三星回单核验台是一个本地 Web 工具，用于批量识别、核验和人工复核三星电子回单。它把 OCR 结果、日期和印章证据、复核记录以及质量统计放在同一个工作流中，适合在本机处理一批图片，也支持按需接入远程识别服务。

## 能做什么

- 导入多张图片或整个文件夹，后台排队识别并显示每张单据的处理进度。
- 识别回单字段、商品明细、签收日期和客户印章，并保存原图、裁剪图和处理后的证据图。
- 自动区分标准回单、商品明细续页、仓库货物接收委托书和未知文档；续页不会被当作一张完整回单重复计算。
- 对日期和印章执行保守匹配。证据不足、存在冲突或时间关系不成立时，记录会进入“待复核”，不会为了提高通过率强行补值。
- 在复核页查看各路原始 OCR、处理图和判定依据，修改字段、日期、印章结论，填写错误类型和备注。
- 在印章中心按签章要求保存一枚标准章，并从后续同要求回单中替换。
- 支持单张或批量确认、重新识别、筛选、历史记录和人工真值维护。首次机器识别值会保留，人工修改不会覆盖评测原值。
- 提供质量概览、字段和商品准确率、错误类型以及不同识别方式的对比。

日期、印章和匹配规则的详细说明见 [`docs/日期识别、印章识别与匹配比较逻辑说明.md`](docs/日期识别、印章识别与匹配比较逻辑说明.md)。项目结构和模块边界见 [`docs/receipt_ocr架构重构说明.md`](docs/receipt_ocr架构重构说明.md)。

## 快速开始

项目使用 Python 运行。当前开发机推荐使用以下 Conda 解释器：

```text
/Users/zhuyihao/anaconda3/bin/python
```

安装依赖：

```bash
python -m pip install -r requirements.txt
```

源码调试时可以启动本地服务：

```bash
python app.py
```

开发调试时可以在浏览器打开 [http://127.0.0.1:5002](http://127.0.0.1:5002)。如果使用推荐解释器，也可以直接运行：

```bash
/Users/zhuyihao/anaconda3/bin/python app.py
```

默认服务只监听本机。可通过环境变量修改监听地址和端口：

```bash
export APP_HOST=127.0.0.1
export APP_PORT=5002
export FLASK_DEBUG=0
```

首次启动会按需准备 PaddleOCR 模型。模型文件较大时，可以把缓存放在容量更大的磁盘：

```bash
export PADDLE_MODEL_HOME="/你的磁盘/OCR"
python app.py
```

## 识别方式

设置页可以分别为印刷字段、商品明细、手写内容、日期和印章选择识别方式。当前支持：

| 方式 | 用途 |
| --- | --- |
| `paddle_v6` | 默认本地识别方式，使用 PP-OCRv6 Small，覆盖字段、商品、日期和印章 |
| `paddle_seal` | 仅用于印章检测和印章区域处理，不负责整页或日期识别 |
| `qingtong` | 可选的远程印章服务 |
| `danzhengtong` | 生产环境远程单证识别，逐张提交并轮询结果 |

识别配置只接受当前 provider 标识；旧的 `paddle`、`paddle_server`、`hybrid`、`hybrid_server` 和 `vision` 不再解析。历史配置需要在保存前改成 `paddle_v6`、`paddle_seal`、`qingtong` 或 `danzhengtong`。

本地整页文字识别先生成去印章色的同尺寸副本，每个选定模型在一次任务中只读取该整页一次并复用结果。签章要求直接从这次整页结果提取，不再额外检测或识别要求行；复核页的要求行处理图是整页输入的局部裁图。日期、印章和二维码仍从原图读取，历史记录需重新识别才会更新。

本地 PP-OCR 默认使用 ONNX Runtime；没有安装或无法使用时会回落到 Paddle 默认 CPU 推理：

```bash
export PADDLE_OCR_ENGINE=onnxruntime
# export PADDLE_OCR_ENGINE=off
```

印章补充识别可通过 `SEAL_SECONDARY_READ_MODE` 控制：

```bash
export SEAL_SECONDARY_READ_MODE=auto   # 默认，仅在安全且有授权时补充读取
# export SEAL_SECONDARY_READ_MODE=local
# export SEAL_SECONDARY_READ_MODE=off
```

补充识别只读取已经生成的印章处理图和展开图，不改变最终匹配门槛。印章公司主体、地名和章型必须来自同一章区的有效证据；文字不完整或出现近似冲突时仍需人工确认。

## 远程服务配置

本地识别默认不会上传图片。只有在设置页明确选择远程方式时，才会向对应服务发送图片。

### 清瞳印章 API

安装版可在软件「设置 → 清瞳服务配置」中粘贴 API 密钥，点击「保存密钥」后立即生效，无需重启。密钥保存在本机应用数据库中，页面和设置接口不会返回已保存的密钥；「清除配置」可停用清瞳。软件中保存的配置优先于环境变量和密钥文件。

把密钥放在 Git 忽略的 `config/seal_api_key` 中，文件只写密钥本身；也可以使用环境变量：

```bash
export SEAL_API_KEY="你的密钥"
export SEAL_API_URL="https://seal.qingtong.cn"
export SEAL_API_TIMEOUT=120
```

未配置密钥时，清瞳选项会显示为不可用。请求同时检查 HTTP 状态和业务状态，失败会保留在记录中，不会覆盖本地结果。

### 单证通

安装版可在「设置 → 远程服务配置 · 单证通」中填写 App ID、App Key、App Secret、Key ID 与回调地址。高级配置预填接口、上传地址及当前三星场景参数；查询超时支持 1–60 秒。保存后立即用于后续识别，密钥留空保留原值，清除配置会停用服务。软件内配置保存在本机数据库中，优先于环境变量及配置文件。

识别方案和核验规则统一以设置页保存的最新配置为准。待开始、排队、失败重试和重新识别的任务，在每张开始执行时读取当前配置；正在执行的单张保持本次配置，下一张使用新配置。历史结果保留实际执行时的配置。


「测试识别」会上传所选回单、提交识别并查询真实结果，可能产生服务费用；不写入正式回单记录。状态区分未配置、配置不完整、已配置和测试通过；修改配置后需重新测试。正在处理的回单继续使用开始识别时的配置。

单证通配置位于 Git 忽略的 `config/danzhengtong.local.json`，也可以用 `.env.example` 中的 `DZT_*` 环境变量覆盖。当前流程是逐张上传、提交并轮询结果；真实接口返回空结果、超时或错误时，该张会明确标记为失败，不会用模拟数据替代。

常用配置项包括：

```bash
export DZT_BASE_URL="https://api.sinotrans.com"
export DZT_APP_ID=""
export DZT_APP_KEY=""
export DZT_APP_SECRET=""
export DZT_KEY_ID=""
export DZT_POLL_TIMEOUT_SECONDS=60
```

详细的接口字段和失败处理见 [`docs/单证通真实接入.md`](docs/单证通真实接入.md)。不要把真实密钥提交到仓库。

## 日常使用流程

1. 在“回单管理”点击“导入回单”，拖入图片或选择文件夹；上传完成后点击页头的“开始识别”。
2. 主表直接显示订单、客户、签名、日期、印章和处理结果；未识别文件也会显示，重新识别期间暂停展示旧核验结论。
3. 点击“任务详情”查看进度、按批次切换、处理排队和失败任务；主表按结论、日期、印章或搜索条件筛选。
4. 打开复核页查看日期和印章的原始/处理图及各路 OCR，必要时修改字段并保存备注。
5. 只有实际日期和印章证据都满足当前通过规则时，才能确认通过；不完整记录继续保持待复核。
6. 在质量概览查看准确率和错误类型。评测只使用数据库保存的机器原值和已维护真值。

系统会保留每次人工修改的前后值、时间和备注。删除记录前会同步清理不再被引用的上传文件、预览图和中间证据图。

## 印章中心

红、蓝印章共用保留笔画明暗的章色分离、方向校正与环形文字展开流程，并抑制表格线、中性黑色核心及其弱色边缘。清瞳定位的印章按原图区域判断实际章色，避免蓝章被当成红章过滤。形状以有效的本地轮廓判断为准：本地确认圆形后不再被清瞳的“椭圆”标签覆盖，只有本地证据不足时才参考远程章型。“四方向择优校正”只接受转正后实际读到可靠章型文字的候选，微调角度不超过 45°；没有可靠候选时保留原方向。黑墨严重覆盖的文字仍可能无法读全，需要人工核对。升级处理算法后，已有回单需点击“重新识别”（样单点击“重新测试”）生成新的处理图和 OCR 结果。

章内单独一行的部门文字（如“仓储部”）与“收货章”等章型文字分别识别，红章、蓝章均支持。部门行的检测识别与单行重读一致、置信度足够时，才与同枚章的环形公司名称合并；复核页可查看每行裁剪图和实际识别文字。

章型行下方的短编号（如“（1）”）会从转正章色图单独裁剪识别，优先沿独立笔画边界紧贴裁剪，减少两侧和下方条纹干扰；只有同一枚章的检测与重读数字一致、置信度足够时才并入章型文字。复核页保留编号裁剪图和原始 OCR；括号缺失不补写，文字比对仍严格区分不同数字。

印章中心首次为空。回单和样单查看页只显示标准章摘要，点击“添加标准章”或“替换标准章”打开独立弹窗：左侧选择候选，右侧预览、对照原图、缩放和调整旋转角度，底部明确保存。印章中心的替换入口也使用同一弹窗。同一枚章有完整可用的本地处理图，且记录能确认它复用了清瞳定位时，只显示本地候选；清瞳识别证据仍保留。只有原始裁剪图、没有完整章色处理图的记录，可以查看但需重新识别后才能加入。取消或关闭弹窗不会保存，也不会关闭下层回单窗口。

已有标准章时，逐枚比较本单的客户印章：同一枚章的识别文字符合签章要求、形状符合标准章，即满足印章条件；不同印章之间不会拼接证据。颜色差异会显示供人工核对，不单独阻止通过。尚无标准章或识别不确定时，也可完成人工核对后确认本单，不会因此自动建档。

在复核页选择新的章后点击“确认替换标准章”，或进入印章中心从同要求回单中选择替换章。图片、识别文字、形状、颜色和来源信息一起更新，每条要求始终只有一枚当前标准章。替换后同要求的待复核回单会重新核对；已确认的人工结论保留。标准图独立保存，来源回单清理不会删除它。

## 样单中心

左侧「样单中心」按标注中的客户名称组织样单。公司目录支持搜索，卡片支持编号搜索、测试状态筛选、分页、原图预览和结果查看；可运行单张、勾选多张或当前公司全部样单。「运行本公司全部」覆盖该公司的所有页，不受编号和状态筛选限制。

测试状态下方的「结果筛选」默认收起，支持展开并组合日期、印章来源、印章结果及签名条件；收起后保留已选条件与命中数量，并记住展开偏好。「更多筛选」可对照另一路印章结果，或按人工标注筛选识别准确性。清瞳模板、清瞳文字 OCR、本地 OCR 和单证通使用各自返回值与判定；未运行、调用失败、未识别和缺少历史结果分别显示。筛选覆盖当前目录全部分页，「运行筛选结果」只提交命中的非测试中样单；修改筛选时会清除勾选，避免操作隐藏样单。

右上角「导入样单」复用回单导入的拖拽区域，支持选择图片、选择文件夹和拖入文件夹（包含子文件夹，跳过非图片文件）。一次导入最多 100 张 JPG、PNG、BMP、WebP 图片，单张最多 20 MB、总计 100 MB。可选择已有客户公司或填写新名称，默认使用当前公司，留空归入「未分类」。同名图片自动重命名，不覆盖原图；导入图片独立保存在 `storage/sample-center/originals/`，公司归类保存在样单数据库。新导入图片尚无日期、印章真值，不计入准确率分母。

勾选单张或多张图片后点击「删除所选」，确认后永久删除样单库记录、对应原图、处理图片及历史测试记录，并释放样单编号；可重新导入到其他公司或未分类。原有数据集中的样单也会删除其对应图片；正式回单和已保存的标准章不受影响。正在排队或运行的样单需等待测试结束。

右上角「统计结果」分别展示日期结果和印章结果，默认取当前公司每张样单最近一次测试，也可选择全部公司或某次测试批次。日期对照人工标注的实际日期；印章按标注的“应匹配／应不匹配”独立评估清瞳模板、清瞳文字 OCR 和各本地模型，不将合并判定当成单路结果。未识别、执行失败计入正确率分母；未测试、未运行、测试中、待标注不计入。支持筛选错误、两路清瞳或清瞳与本地判定不一致，并打开原有样单预览。

选择客户公司后，可在右侧公司标题下编辑「未标记、待检查、已检查、有问题」和最多 500 字备注；搜索框下用状态按钮筛选。公司列表中的「✓」表示印章中心已有对应标准章，按样单标注的签章要求关联；右侧会区分全部收录和部分收录，悬停可查看覆盖数量。人工标记与绿色的测试完成状态独立，保存在样单数据库，刷新和重启后保留。已检查的公司产生新的测试结果（含运行失败）时提示「有新测试结果」；仅修改备注不会清除提示，查看后勾选「确认已检查当前结果」再保存才会更新检查进度。

预览不触发识别。测试使用点击运行时已保存的当前配置，后台执行并自动更新状态，重复提交会跳过已在测试中的样单。「测试记录」保留最近 200 次单张测试入口，结果继续使用现有只读查看窗口，支持整页、日期、印章与识别依据查看。样单结果不能提交为正式回单的人工复核结论。

测试任务、结果和生成图片保存在 `storage/sample-center/`，不进入正式回单列表、业务队列或质量统计，也不受正式回单的保留天数清理影响。原有正式库中的历史记录保持原样；设置页中的旧样单按钮已替换为样单中心入口。

## 初始化数据迁移

在「设置 → 初始化数据」点击「导出数据包」，下载 ZIP 文件。在另一台电脑部署同版本程序后，进入相同位置点击「导入数据包」。完成后点击「刷新查看」更新样单中心和印章中心。

可先选择「仅样单」「仅标准章」或「样单和标准章」，分别导出、导入。旧版合并数据包也支持只导入选中的部分；图片保留原文件，不缩小分辨率或进行有损压缩。

- 数据包包含当前未删除的样单原图及标注（包括 `数据/` 中的内置样单和后来导入的样单），以及当前标准章图片、签章要求、识别文字、章型、颜色和来源文件名；不依赖来源电脑的目录。
- 不包含正式回单、测试结果、历史版本、公司检查标记、任务队列、识别配置或服务密钥。导入样单初始状态为「未测试」，标准章用于后续核验；已有回单的复核结论保留。
- 导入只增加缺少的数据。同名样单（含已删除或已有任务的名称）、同签章要求的标准章跳过，保留本机数据；重复导入不会重复添加。不同名称的相同图片仍视为不同样单。
- 全包检查通过后才写入，两个数据库在同一事务中更新；失败会回滚并清除本次新建图片。不会覆盖本机数据库或修改 `数据/` 中的文件。
- 当前支持版本 1 的 ZIP 数据包，最多 10000 项，原图合计不超过 450 MB，单图不超过 20 MB。

识别中间图不进入初始化数据包。每次识别仍保留独立历史结果；新完成的单次识别中，内容完全相同的处理图会复用同一文件，并同步更新该结果各处的图片引用。原图及印章候选身份引用保持独立，不影响人工核对。已有历史图片不会在升级时自动删除。

如果需要通过 Git 分发，可将导出的 ZIP 放在 `storage/`、`outputs/` 以外的目录（例如 `deployment-data/`）再纳入版本控制。另一台电脑拉取后手动导入；拉取代码不会自动改写本机数据。不要直接提交运行数据库或密钥。

## 数据与目录

| 路径 | 内容 |
| --- | --- |
| `数据/` | 样单图片、`ground_truth.json` 和文档分流真值 |
| `storage/results.db` | 识别结果、任务、复核历史和运行信息 |
| `storage/sample-center/` | 独立样单测试数据库、预览图和处理证据图 |
| `storage/uploads/` | 上传图片的本地副本 |
| `storage/previews/` | 复核页使用的预览图 |
| `storage/artifacts/` | 日期、印章和其他阶段的证据图 |
| `storage/seal-standards/` | 手动保存的完整标准章图及其历史版本，不随来源回单清理 |
| `storage/exports/` | 运行时生成的导出文件 |
| `config/` | 本机配置和密钥文件；真实密钥不应提交 |

源码运行时数据保存在项目的 `storage/`。Windows 打包程序默认把运行数据放在 `%LOCALAPPDATA%\\SamsungReceipt`，也可以用 `SAMSUNG_RECEIPT_DATA_DIR` 指定目录。

## 离线验收与开发检查

对已维护真值的样单运行端到端验收：

```bash
python -m tools.analysis.operations.e2e_six --backend paddle_v6
```

只验证复核闭环时，可运行六张基线并模拟人工操作：

```bash
python -m tools.analysis.operations.e2e_six \
  --backend paddle_v6 \
  --limit 6 \
  --exercise-review \
  --report-path storage/e2e-six-acceptance.json
```

不启动 Web 服务生成质量报表：

```bash
python -m tools.analysis.operations.generate_report \
  --backend paddle_v6 \
  --output storage/accuracy-report-paddle-v6.json
```

新增样单并写入数据库：

```bash
python -m tools.analysis.operations.batch_validate \
  --backend paddle_v6 \
  --filename 你的文件名.jpg \
  --save-db \
  --output storage/new-sample.json
```

文档分流和后端对比使用独立命令，避免把续页或委托书混入标准回单准确率：

```bash
python -m tools.analysis.operations.evaluate_document_routing \
  --task-id <批次 ID> \
  --output storage/document-routing-report.json

python -m tools.analysis.operations.compare_backend_runs \
  --run local=storage/local-run.json \
  --reference-backend local \
  --output storage/backend-comparison.json
```

运行完整测试：

```bash
python -m pytest -q
```

Windows 首次运行建议先做环境自检：

```powershell
python -m tools.analysis.operations.windows_smoke --output storage\\windows-smoke.json
python -m pytest tests/test_ocr_backends.py tests/test_platform_runtime.py -q
```

## 代码结构

```text
receipt_ocr/
├── application/       用例编排和识别计划
├── domain/             阶段、字段、商品和文档规则
├── stages/             字段、商品、日期、手写和印章阶段
├── recognition/        日期与印章证据算法
├── providers/          OCR 后端和远程服务适配
├── imaging/            裁剪、预处理和证据图
├── persistence/        SQLite 仓储
├── jobs/               后台任务和队列
├── runtime/            路径、进度和运行策略
├── web/                Flask 应用与 HTTP 路由
└── api/                对外结果序列化
```

新增识别阶段时，先在 `domain/stages.py` 注册阶段，再实现领域结果和阶段入口；新增 OCR 后端时，先在 provider registry 声明能力，再接入具体运行时。业务规则不应直接依赖模型名称，证据生成和最终判定应分开保存。

## Windows 桌面安装包

Windows 用户使用 Tauri 桌面安装包。GitHub Actions 在 Windows 服务器上完成 Python/OCR 服务打包、Tauri 构建和 NSIS 安装包生成；推送 `v*` 标签后，安装包会作为 GitHub Release 附件发布，也可以在 Actions 页面手动运行工作流。

开发机可以在 `desktop/` 下执行：

```bash
cd desktop
pnpm install
pnpm tauri:dev:mac
```

Windows 本地构建脚本为 `desktop/scripts/build_installer.ps1`。它会先构建内部识别服务，再将服务作为桌面端资源打入 NSIS 安装包。用户只需要安装生成的桌面软件，窗口关闭时会同步结束本次启动的本地服务。
