# 三星回单核验台

三星回单核验台是一个本地 Web 工具，用于批量识别、核验和人工复核三星电子回单。它把 OCR 结果、日期和印章证据、复核记录以及质量统计放在同一个工作流中，适合在本机处理一批图片，也支持按需接入远程识别服务。

## 能做什么

- 导入多张图片或整个文件夹，后台排队识别并显示每张单据的处理进度。
- 识别回单字段、商品明细、签收日期和客户印章，并保存原图、裁剪图和处理后的证据图。
- 自动区分标准回单、商品明细续页、仓库货物接收委托书和未知文档；续页不会被当作一张完整回单重复计算。
- 对日期和印章执行保守匹配。证据不足、存在冲突或时间关系不成立时，记录会进入“待复核”，不会为了提高通过率强行补值。
- 在复核页查看各路原始 OCR、处理图和判定依据，修改字段、日期、印章结论，填写错误类型和备注。
- 在印章中心按签章要求保存一枚标准章，并从后续同要求回单中替换。
- 支持单张或批量确认、重新识别、筛选、历史记录和人工真值维护。首次机器识别值会保留，人工修改不会覆盖评测原值。
- 提供质量概览、字段和商品准确率、错误类型以及不同识别方式的对比。

日期、印章和匹配规则的详细说明见 [`docs/日期识别、印章识别与匹配比较逻辑说明.md`](docs/日期识别、印章识别与匹配比较逻辑说明.md)。项目结构和模块边界见 [`docs/receipt_ocr架构重构说明.md`](docs/receipt_ocr架构重构说明.md)。

## 快速开始

项目使用 Python 运行。当前开发机推荐使用以下 Conda 解释器：

```text
/Users/zhuyihao/anaconda3/bin/python
```

安装依赖：

```bash
python -m pip install -r requirements.txt
```

源码调试时可以启动本地服务：

```bash
python app.py
```

开发调试时可以在浏览器打开 [http://127.0.0.1:5002](http://127.0.0.1:5002)。如果使用推荐解释器，也可以直接运行：

```bash
/Users/zhuyihao/anaconda3/bin/python app.py
```

默认服务只监听本机。可通过环境变量修改监听地址和端口：

```bash
export APP_HOST=127.0.0.1
export APP_PORT=5002
export FLASK_DEBUG=0
```

首次启动会按需准备 PaddleOCR 模型。模型文件较大时，可以把缓存放在容量更大的磁盘：

```bash
export PADDLE_MODEL_HOME="/你的磁盘/OCR"
python app.py
```

## 识别方式

设置页可以分别为印刷字段、商品明细、手写内容、日期和印章选择识别方式。当前支持：

| 方式 | 用途 |
| --- | --- |
| `paddle_v6` | 默认本地识别方式，使用 PP-OCRv6 Small，覆盖字段、商品、日期和印章 |
| `paddle_seal` | 仅用于印章检测和印章区域处理，不负责整页或日期识别 |
| `qingtong` | 可选的远程印章服务 |
| `danzhengtong` | 生产环境远程单证识别，逐张提交并轮询结果 |

识别内容与整单判定分开：已选内容照常识别并判断是否匹配；核验规则中的“不计入判定”只排除该项对整单通过、拒绝或复核的影响，保留真实匹配结果。印刷字段和手写内容的多路差异保留在识别依据中，不额外增加通过条件；整单按已启用的日期、印章、签名与低置信度规则判定。联系人中的 `、`、逗号、斜杠、分号和竖线按等价分隔符比较，各路原始文本保留。

印刷字段与仓库接收人的有效识别值不一致时，优先采用单证通结果；单证通未返回该字段、返回失败或字段格式无效时，使用其他可用结果。原始识别值与各自来源保留供对照。

识别配置只接受当前 provider 标识；旧的 `paddle`、`paddle_server`、`hybrid`、`hybrid_server` 和 `vision` 不再解析。历史配置需要在保存前改成 `paddle_v6`、`paddle_seal`、`qingtong` 或 `danzhengtong`。

本地整页文字识别先生成去印章色的同尺寸副本，每个选定模型在一次任务中只读取该整页一次并复用结果。签章要求直接从这次整页结果提取，不再额外检测或识别要求行；复核页的要求行处理图是整页输入的局部裁图。日期、印章和二维码仍从原图读取，历史记录需重新识别才会更新。

本地 PP-OCR 默认使用 ONNX Runtime；没有安装或无法使用时会回落到 Paddle 默认 CPU 推理：

```bash
export PADDLE_OCR_ENGINE=onnxruntime
# export PADDLE_OCR_ENGINE=off
```

印章补充识别可通过 `SEAL_SECONDARY_READ_MODE` 控制：

```bash
export SEAL_SECONDARY_READ_MODE=auto   # 默认，仅在安全且有授权时补充读取
# export SEAL_SECONDARY_READ_MODE=local
# export SEAL_SECONDARY_READ_MODE=off
```

补充识别只读取已经生成的印章处理图和展开图，不改变最终匹配门槛。印章公司主体、地名和章型必须来自同一章区的有效证据；文字不完整或出现近似冲突时仍需人工确认。

本地红色收货表格章会按实际用途行区分仓库名、代码、章型和章号，以及收货人、日期填写栏。完整格线与同方向收货人确认的日期格，其内容不参与印章文字核对，空白、读不到或读成乱码都不会因此阻止匹配。原逐行读数保留，补读会核对同一物理行的检测结果；证据不足时才用完整外框和格线验证的彩色、色差灰度两路补充身份文字，不跨章或跨方向拼接。

仓库名和完整代码之间存在真实空隙时，会增加同一首行的分段补读。分段候选、原整行文字、置信度和实际输入图均可在复核页查看；可靠读数存在 `0/O`、仓名或章号分歧时，分段候选仅供核对，不自动放行。已有匹配不会因可选补读失败而被撤销，标准章检查也不会重新使用被阻断的旧聚合文字。历史结果需要重新测试或重新识别才会生成这些新证据。独立签收日期环节仍由设置页的日期方案和验收配置控制。

章内数字编号兼容单个括号字母误读：章型文字后的 `（i）` / `（I）`，或独立定位编号区中的同类结果，按 `（1）` 比较。原始 OCR 与编号图保留；公司名、代码、站号中的字母及无括号字母不替换，其他数字冲突仍按不匹配处理。

本地 PP-OCRv6 对“独立章型＋短编号”的环章，在原下弧没有可靠文字且识别正常完成时，沿实测边框同向连续展开公司名，避免将圆心下方的首尾拆成反向下弧。已有可靠下弧文字（包含电话及其他未知文字）的章保留原分区；失败的下弧 OCR 不触发切换。统一使用文字带比例与图像空隙定位，不用签章要求补字或选参数。原分段图片、原始读数保留为核对证据，复核页默认显示实际采用的连续展开图。历史识别结果不会自动回写，需要重新识别才会应用新规则。

## 远程服务配置

本地识别默认不会上传图片。只有在设置页明确选择远程方式时，才会向对应服务发送图片。

### 清瞳印章 API

安装版可在软件「设置 → 清瞳服务配置」中粘贴 API 密钥，点击「保存密钥」后立即生效，无需重启。密钥保存在本机应用数据库中，页面和设置接口不会返回已保存的密钥；「清除配置」可停用清瞳。软件中保存的配置优先于环境变量和密钥文件。

把密钥放在 Git 忽略的 `config/seal_api_key` 中，文件只写密钥本身；也可以使用环境变量：

```bash
export SEAL_API_KEY="你的密钥"
export SEAL_API_URL="https://seal.qingtong.cn"
export SEAL_API_TIMEOUT=120
```

未配置密钥时，清瞳选项会显示为不可用。请求同时检查 HTTP 状态和业务状态，失败会保留在记录中，不会覆盖本地结果。

同时选择清瞳和本地识别时，清瞳图片请求在本地整页 OCR 前发起，与整页识别重叠；字段准备好后再比较印章结果。只有网络取证提前，文档分流与结果核验仍由主流程完成；已明确不适用印章识别的文档不预取。

### 单证通

安装版可在「设置 → 远程服务配置 · 单证通」中填写 App ID、App Key、App Secret、Key ID 与回调地址。高级配置分别提供整页场景 ID（默认 `logistics_samsung_deliverynote_1503`）和印章场景 ID（默认 `logistics_samsung_outseal_1503`），两者复用账号、上传地址、系统编码和组织 ID；查询超时支持 1–60 秒。保存后立即用于后续识别，密钥留空保留原值，清除配置会停用服务。软件内配置保存在本机数据库中，优先于环境变量及配置文件。旧配置未包含印章场景 ID 时自动采用默认值。

单证通印章使用独立印章场景识别颜色、类型和文字。上传前按整页位置排除发货单位章；对低处左侧的明显横椭圆章，结合右侧客户章位置确认后跳过，保留偏左下的圆形客户章及不确定候选。上传完整的章色增强子图，保留原方向，由单证通旋正；返回图片下载成功后，复核直接使用该旋正图。返回地址无法访问时保留识别文字并明确提示图片下载失败。整页场景继续提取回单字段、签收填写和日期。

识别方案和核验规则统一以设置页保存的最新配置为准。待开始、排队、失败重试和重新识别的任务，在每张开始执行时读取当前配置；正在执行的单张保持本次配置，下一张使用新配置。历史结果保留实际执行时的配置。


「整页连通测试」会上传所选回单、提交整页场景并查询真实结果，可能产生服务费用；不写入正式回单记录。此处测试的是整页场景的上传、提交和查询，印章场景在正式印章识别时单独调用。状态区分未配置、配置不完整、已配置和测试通过；修改配置后需重新测试。正在处理的回单继续使用开始识别时的配置。

单证通配置位于 Git 忽略的 `config/danzhengtong.local.json`，也可以用 `.env.example` 中的 `DZT_*` 环境变量覆盖。当前流程是逐张上传、提交并轮询结果；真实接口返回空结果、超时或错误时，该张会明确标记为失败，不会用模拟数据替代。

常用配置项包括：

```bash
export DZT_BASE_URL="https://api.sinotrans.com"
export DZT_APP_ID=""
export DZT_APP_KEY=""
export DZT_APP_SECRET=""
export DZT_KEY_ID=""
export DZT_SEAL_MODEL_ID="logistics_samsung_outseal_1503"
export DZT_POLL_TIMEOUT_SECONDS=60
```

详细的接口字段和失败处理见 [`docs/单证通真实接入.md`](docs/单证通真实接入.md)。不要把真实密钥提交到仓库。

## 日常使用流程

1. 在“回单管理”点击“导入回单”，拖入图片或选择文件夹；上传完成后点击页头的“开始运行”。一次启动设置中已启用的识别来源；勾选时只运行所选待开始回单。常规识别与单证通分别显示进度；已有结果满足通过规则时先通过，否则等待已启用的单证通返回后判定。
2. 主表直接显示订单、客户、签名、日期、印章和处理结果；未识别文件也会显示，重新识别期间暂停展示旧核验结论。
3. 回单管理默认使用专注布局；点击页头“任务状态”打开任务详情，按当天全部回单查看进度、处理排队和失败任务，以及调整单证通查询设置。同一天多次导入统一展示，不需要选择批次；“查看当天回单”打开当天全部记录。主表按结论、日期、印章或搜索条件筛选；“复核当前筛选”位于列表右上角的更多操作中。
4. 打开复核页查看日期和印章的原始/处理图及各路 OCR，必要时修改字段并保存备注。
5. 只有实际日期和印章证据都满足当前通过规则时，才能确认通过；不完整记录继续保持待复核。
6. 在质量概览查看准确率和错误类型。评测只使用数据库保存的机器原值和已维护真值。

系统会保留每次人工修改的前后值、时间和备注。删除记录前会同步清理不再被引用的上传文件、预览图和中间证据图。

回单和样单查看页的“本次识别明细”打开独立的大弹窗，按同一时间刻度展示本地整页、日期、印章、清瞳、单证通整页和单证通印章的并行区间，展开查看逐次调用；每枚单证通印章保留自己的提交、查询及等待记录。旧记录无法确认场景时显示“单证通（未分类）”。顶部全流程历时按实际开始到结果保存完成的共同时间跨度计算，包含初始化、图像处理、接口等待和结果整理，不再把并行分支的耗时相加。模型初始化仍单独展示供比较，已计入全流程历时。旧记录缺少最后的保存时间时，明确显示约值和“截至结果取回”；上传起点等关键边界缺失时，总历时显示未记录。

完整重新识别保留最近一次处理的明细；样单补充运行单证通时，保留此前其他方法已有的明细，并在单独的“此前保留的识别”时间轴展示，本次总历时只计算新执行的运行。异步单证通的上传、轮询不另算识别次数；提交与查询累计仍是实际请求耗时，不含等待间隔。印章子图的单独识别分别计数，裁剪和缓存复用不计为新调用。明细只引用已有证据图，不额外复制图片。旧数据未采集的逐次调用明细与耗时不作推算；已有受理编号可确认的单证通调用显示一次，未采集的耗时显示未记录。

“远程接口耗时”单独展示清瞳和单证通。清瞳分列本机请求耗时与服务端返回的处理时间；单证通分列上传、提交、查询的请求耗时，以及包含等待间隔的到结果总历时。新运行记录每次实际请求的起止区间；只有请求区间完整时才在时间轴上显示其间的等待、调度间隔，该间隔不代表纯服务端计算时间。旧记录只展示已采集的累计时间，缺失分项标为未记录；由历史受理和取回时间戳计算的历时标为约值，不根据累计秒数猜测各次查询的位置。补充单证通时继续保留此前清瞳的计时。

明细中的“图像处理”可展开查看旋转校正、区域裁剪、颜色分离、去噪增强、文字展开等项目的次数和累计耗时。累计值排除嵌套处理和内部同步识别的重复时间；时间轴另行保留操作的完整起止区间，便于查看重叠，不用于重复相加。这里只保存轻量计时记录，不额外复制图片。旧记录没有采集区间或单独图像耗时时显示未记录，重新测试后即可查看。

样单查看页的“问题标记与备注”支持多选。发现的问题关联当前测试结果，重新测试后重新核对；图片与版式特征、补充备注跨测试保留。“尚未标注”“已核对无问题”“已发现问题”分别记录，不把未选择当成无问题。旧单选标记继续保留，未能确定测试归属的旧问题需人工核对后沿用。

系统会根据已保存的人工标注与本次识别结果预填日期读错、漏识别、印章判定错误等可确认的问题，并显示预填提示。印章问题分为“清瞳印章”和“本地印章”，分别记录未检出、文字问题、判定错误、证据不足和识别失败；某一路有问题时，当前采用的印章结论仍可能匹配。预填依据会直接列出来源与差异；无法确定来源的历史标记保留原名。这些仅为草稿，核对保存后才计入人工标记；已保存的人工选择不会被覆盖，可通过“带入检测到的问题”补选建议。图片模糊、遮挡等特征仍由人工选择。样单统计和 Excel 分别展示人工问题与自动评测，人工标签不改变识别正确率；每张样单每个标签计一次，多选标签数量合计可能超过样单数。

## 印章中心

标准章档案按签章要求中完整、准确的公司、机构或仓库名称归组，分公司、用途、章号、站点编号、仓库代码和电话在组内分别展示。通用三星服务／维修中心标为“同名归档”，各站点仍独立核验。所有目录统一显示名称、折叠箭头和档案条数，默认收起；只有一条的目录也显示“1 条”，展开后查看印章卡片。归组仅便于查找，不合并标准图，也不改变核验规则。搜索名称、分支、代码、电话或章号会直接展开命中项，清空搜索恢复手动展开状态，刷新保留当前选择和展开状态。详情展示完整签章要求与识别文字，支持原位缩放、查看来源回单或样单，以及切换同组其他标准章；关闭来源查看后回到印章中心。

印章中明确标注、号码完整的“维修热线”按电话字段核对。签章要求未列电话时，可作为附加联系信息保留；要求已列电话时，号码必须一致。名称、分支、用途、站点和编号仍独立严格核对，原始识别文字不删改。

本地整页印章定位使用随项目内置的清瞳 YOLO11s ONNX 模型，采用 640×640 等比补边输入，置信度阈值 0.55、NMS IoU 阈值 0.1。模型框直接用于裁章，不再经过旧的颜色轮廓拆分与页面尺寸、位置过滤；模型正常返回无章时保留空结果，仅加载或推理失败时回退颜色轮廓定位并记录日志。清瞳接口已有框时仍优先复用。权重随源码及安装包分发，运行不依赖交付资料所在外置盘；安装版权重统一保存在 `models/official_models/QingTong-YOLO11s-seal_det/`，并参与本地模型的初始化、状态展示和释放。

红、蓝印章共用保留笔画明暗的章色分离、方向校正与环形文字展开流程，并抑制表格线、中性黑色核心及其弱色边缘。后续原色增强保留原生分辨率上已确认的章色笔画，避免灰红、灰蓝文字再次被色差重建压淡；笔画下限来自原图，不从旧处理图补回噪声。清瞳定位的印章按原图区域判断实际章色，避免蓝章被当成红章过滤。形状以有效的本地轮廓判断为准：本地确认圆形后不再被清瞳的“椭圆”标签覆盖，只有本地证据不足时才参考远程章型。“四方向择优校正”只接受转正后实际读到可靠章型文字的候选，微调角度不超过 45°；没有可靠候选时保留原方向。黑墨严重覆盖的文字仍可能无法读全，需要人工核对。升级处理算法后，已有回单需点击“重新识别”（样单点击“重新测试”）生成新的处理图和 OCR 结果。

章内单独一行的部门文字（如“仓储部”）与“收货章”等章型文字分别识别，红章、蓝章均支持。部门行的检测识别与单行重读一致、置信度足够时，才与同枚章的环形公司名称合并；复核页可查看每行裁剪图和实际识别文字。

章型行下方的短编号（如“（1）”）会从转正章色图单独裁剪识别，优先沿独立笔画边界紧贴裁剪，减少两侧和下方条纹干扰；只有同一枚章的检测与重读数字一致、置信度足够时才并入章型文字。复核页保留编号裁剪图和原始 OCR；括号缺失不补写，文字比对仍严格区分不同数字。

印章中心首次为空。回单和样单查看页只显示标准章摘要，点击“添加标准章”或“替换标准章”打开独立弹窗：左侧选择候选，右侧预览、对照原图、缩放和调整旋转角度，底部明确保存。印章中心的替换入口也使用同一弹窗。同一枚章有完整可用的本地处理图，且记录能确认它复用了清瞳定位时，只显示本地候选；清瞳识别证据仍保留。只有原始裁剪图、没有完整章色处理图的记录，可以查看但需重新识别后才能加入。取消或关闭弹窗不会保存，也不会关闭下层回单窗口。

已有标准章时，逐枚比较本单的客户印章：同一枚章的识别文字符合签章要求、形状符合标准章，即满足印章条件；不同印章之间不会拼接证据。颜色差异会显示供人工核对，不单独阻止通过。尚无标准章或识别不确定时，也可完成人工核对后确认本单，不会因此自动建档。

在复核页选择新的章后点击“确认替换标准章”，或进入印章中心从同要求回单中选择替换章。图片、识别文字、形状、颜色和来源信息一起更新，每条要求始终只有一枚当前标准章。替换后同要求的待复核回单会重新核对；已确认的人工结论保留。标准图独立保存，来源回单清理不会删除它。

标准章图片按签章要求命名（如 `某公司收货专用章.png`），替换版本添加 ` - v2` 等版本号；不适合文件名的字符会替换为下划线，长名称会截短，同名文件添加序号。保存和导入使用同一命名规则。启动时自动将旧随机文件名改为对应签章要求，历史图片链接仍可访问，识别记录和档案版本保持原样。

## 样单中心

左侧「样单中心」按标注中的客户名称组织样单。公司目录支持搜索，卡片支持编号搜索、测试状态筛选、分页、原图预览和结果查看；可运行单张、勾选多张或当前公司全部样单。「开始运行」覆盖当前公司的所有页，未选择公司时覆盖全部样单，不受编号和状态筛选限制。

多路日期识别优先显示可靠的匹配结果；都未匹配时，显示距「要求到货」最近的完整日期，天数差相同时保留原顺序。日期更接近仍按原核对规则判断，不视为匹配；各路原始日期和识别依据继续保留，人工确认的日期不自动替换。

测试状态下方的「结果筛选」默认收起，支持展开并组合日期、印章来源、印章结果及签名条件；收起后保留已选条件与命中数量，并记住展开偏好。「更多筛选」可对照另一路印章结果，或按人工标注筛选识别准确性。清瞳模板、清瞳文字 OCR、本地 OCR 和单证通使用各自返回值与判定；未运行、调用失败、未识别和缺少历史结果分别显示。筛选覆盖当前目录全部分页，「运行筛选结果」只提交命中的非测试中样单；修改筛选时会清除勾选，避免操作隐藏样单。

右上角「导入样单」复用回单导入的拖拽区域，支持选择图片、选择文件夹和拖入文件夹（包含子文件夹，跳过非图片文件）。一次导入最多 100 张 JPG、PNG、BMP、WebP 图片，单张最多 20 MB、总计 100 MB。可选择已有客户公司或填写新名称，默认使用当前公司，留空归入「未分类」。相同编号的图片跨扩展名跳过，不覆盖原图；导入图片独立保存在 `storage/sample-center/originals/`，公司归类保存在样单数据库。新导入图片尚无日期、印章真值，不计入准确率分母。

上传样单的文件名不符合现有编号格式时，测试识别成功后自动改为识别到的 10 位「客户订单号」，保留图片扩展名及 `-01`、`_01` 等续页后缀。已有编号名保持原样；未识别到有效编号或编号已占用时保留原名，重名原因记录在处理历史中。改名同步保留公司分类、人工标注和全部测试历史，原图内容保持不变。

勾选单张或多张图片后点击「删除所选」，确认后永久删除样单库记录、对应原图、处理图片及历史测试记录，并释放样单编号；可重新导入到其他公司或未分类。原有数据集中的样单也会删除其对应图片；正式回单和已保存的标准章不受影响。正在排队或运行的样单需等待测试结束。

右上角「统计结果」分别展示日期结果和印章结果。「统计范围」默认使用每张样单最近一次测试，保留未测试样单；可切换为指定测试批次，查看名称、时间、状态和实际识别方案。最新结果可能混合不同时间与方案，不会为某一路单独补取旧结果。概览展示标注覆盖、实际参与评测数量、异常样单、各方案正确率、错误分类，以及按公司或签章要求的汇总；多方案增加同一组可评测样单的对比与判定分歧。印章区分误放行、误拒绝、部分匹配、未识别和执行失败；日期分开评估有日期和空白日期，列出读错、漏读和空白误读。点击异常数量可按方案、公司或签章要求进入对应样单明细，查看缩略图、标注、识别文字、判定及测试来源，并导出当前范围的 Excel 汇总和全部明细。

Excel 固定包含「统计总览」「样单明细」两张工作表，默认打开总览；总览集中展示范围、关键数量、各方案表现与分组分析，明细按样单逐行保留标注、各方案结果、测试来源和人工备注，支持冻结表头、筛选及状态着色。点击导出后，统计弹窗内显示生成进度、已发起下载或失败重试提示；生成期间禁止重复提交，关闭弹窗会取消尚未完成的导出。

日期对照人工标注的实际日期；印章按标注的“应匹配／应不匹配”独立评估清瞳模板、清瞳文字 OCR 和各本地模型，不将合并判定当成单路结果，也不代表逐字转写准确率。未识别、执行失败计入正确率分母；未测试、未运行、测试中、待标注不计入。批次历史结果仍与当前人工标注比较。

选择客户公司后，可在右侧公司标题下编辑「未标记、待检查、已检查、有问题」和最多 500 字备注；搜索框下用状态按钮筛选。公司列表中的「✓」表示印章中心已有对应标准章，按样单标注的签章要求关联；右侧会区分全部收录和部分收录，悬停可查看覆盖数量。人工标记与绿色的测试完成状态独立，保存在样单数据库，刷新和重启后保留。已检查的公司产生新的测试结果（含运行失败）时提示「有新测试结果」；仅修改备注不会清除提示，查看后勾选「确认已检查当前结果」再保存才会更新检查进度。

预览不触发识别。测试使用点击运行时已保存的当前配置，后台执行并自动更新状态，重复提交会跳过已在测试中的样单。「测试记录」保留最近 200 次单张测试入口，结果继续使用现有只读查看窗口，支持整页、日期、印章与识别依据查看。样单结果不能提交为正式回单的人工复核结论。

测试任务、结果和生成图片保存在 `storage/sample-center/`，不进入正式回单列表、业务队列或质量统计，也不受正式回单的保留天数清理影响。原有正式库中的历史记录保持原样；设置页中的旧样单按钮已替换为样单中心入口。

运行按钮旁的测试方式适用于公司全部、筛选结果、勾选和单张测试，选择会保存在当前浏览器。可选「只本地」「只清瞳」「只单证通」「本地 + 单证通」「全部一起」；本地使用设置中已选的本地模型，清瞳仅测试印章并沿用样单已有字段，全部一起同时包含三路。单证通独立提交、查询和回填，等待期间保留常规结果。每次测试会保存当时的方式与配置，卡片及测试记录可查看使用的方式；后续修改设置不影响已排队的测试。

「只单证通」按增量更新：保留已有本地、清瞳各路结果、各自判定及图片依据，返回后仅替换单证通这一组结果，再生成综合结果；等待或查询失败时仍可查看已有结果。此前已运行的单证通单独测试，在重新启动服务后会从保留的历史记录补回其他渠道，已取回的单证通报文直接复用，不重新上传。

测试方式菜单使用页面统一样式，支持键盘选择。点击「开始运行」后，按钮显示本次运行的已处理数量，下方进度条同步更新排队、识别中、单证通待返回及需处理数量；只有常规识别和单证通都结束才计入本次已处理。刷新页面后继续跟踪同一次运行，历史已完成数量不计入新运行进度。

## 初始化数据迁移

在「设置 → 数据管理 → 样单与标准章迁移」点击「导出数据包」，下载 ZIP 文件。在另一台电脑部署同版本程序后，进入相同位置点击「导入数据包」。完成后点击「刷新查看」更新样单中心和印章中心。

可先选择「仅样单」「仅标准章」或「样单和标准章」，分别导出、导入。旧版合并数据包也支持只导入选中的部分；图片保留原文件，不缩小分辨率或进行有损压缩。

- 数据包包含当前未删除的样单原图及标注（包括 `数据/` 中的内置样单和后来导入的样单），以及当前标准章图片、签章要求、识别文字、章型、颜色和来源文件名；不依赖来源电脑的目录。
- 不包含正式回单、测试结果、历史版本、公司检查标记、任务队列、识别配置或服务密钥。导入样单初始状态为「未测试」，标准章用于后续核验；已有回单的复核结论保留。
- 导入只增加缺少的数据。同名样单（含已删除或已有任务的名称）、同签章要求的标准章跳过，保留本机数据；重复导入不会重复添加。不同名称的相同图片仍视为不同样单。
- 全包检查通过后才写入，两个数据库在同一事务中更新；失败会回滚并清除本次新建图片。不会覆盖本机数据库或修改 `数据/` 中的文件。
- 当前支持版本 1 的 ZIP 数据包，最多 10000 项，原图合计不超过 450 MB，单图不超过 20 MB。

识别中间图不进入初始化数据包。每次识别仍保留独立历史结果；新完成的单次识别中，内容完全相同的处理图会复用同一文件，并同步更新该结果各处的图片引用。原图及印章候选身份引用保持独立，不影响人工核对。已有历史图片不会在升级时自动删除。

如果需要通过 Git 分发，可将导出的 ZIP 放在 `storage/`、`outputs/` 以外的目录（例如 `deployment-data/`）再纳入版本控制。另一台电脑拉取后手动导入；拉取代码不会自动改写本机数据。不要直接提交运行数据库或密钥。

## 数据与目录

| 路径 | 内容 |
| --- | --- |
| `数据/` | 样单图片、`ground_truth.json` 和文档分流真值 |
| `storage/results.db` | 识别结果、任务、复核历史和运行信息 |
| `storage/sample-center/` | 独立样单测试数据库、预览图和处理证据图 |
| `storage/uploads/` | 上传图片的本地副本 |
| `storage/previews/` | 复核页使用的预览图 |
| `storage/artifacts/` | 日期、印章和其他阶段的证据图 |
| `storage/seal-standards/` | 手动保存的完整标准章图及其历史版本，不随来源回单清理 |
| `storage/exports/` | 运行时生成的导出文件 |
| `config/` | 本机配置和密钥文件；真实密钥不应提交 |

源码运行时数据保存在项目的 `storage/`。Windows 打包程序默认把运行数据放在 `%LOCALAPPDATA%\\SamsungReceipt`，也可以用 `SAMSUNG_RECEIPT_DATA_DIR` 指定目录。

## 离线验收与开发检查

对已维护真值的样单运行端到端验收：

```bash
python -m tools.analysis.operations.e2e_six --backend paddle_v6
```

只验证复核闭环时，可运行六张基线并模拟人工操作：

```bash
python -m tools.analysis.operations.e2e_six \
  --backend paddle_v6 \
  --limit 6 \
  --exercise-review \
  --report-path storage/e2e-six-acceptance.json
```

不启动 Web 服务生成质量报表：

```bash
python -m tools.analysis.operations.generate_report \
  --backend paddle_v6 \
  --output storage/accuracy-report-paddle-v6.json
```

新增样单并写入数据库：

```bash
python -m tools.analysis.operations.batch_validate \
  --backend paddle_v6 \
  --filename 你的文件名.jpg \
  --save-db \
  --output storage/new-sample.json
```

文档分流和后端对比使用独立命令，避免把续页或委托书混入标准回单准确率：

```bash
python -m tools.analysis.operations.evaluate_document_routing \
  --task-id <批次 ID> \
  --output storage/document-routing-report.json

python -m tools.analysis.operations.compare_backend_runs \
  --run local=storage/local-run.json \
  --reference-backend local \
  --output storage/backend-comparison.json
```

运行完整测试：

```bash
python -m pytest -q
```

Windows 首次运行建议先做环境自检：

```powershell
python -m tools.analysis.operations.windows_smoke --output storage\\windows-smoke.json
python -m pytest tests/test_ocr_backends.py tests/test_platform_runtime.py -q
```

## 代码结构

```text
receipt_ocr/
├── application/       用例编排和识别计划
├── domain/             阶段、字段、商品和文档规则
├── stages/             字段、商品、日期、手写和印章阶段
├── recognition/        日期与印章证据算法
├── providers/          OCR 后端和远程服务适配
├── imaging/            裁剪、预处理和证据图
├── persistence/        SQLite 仓储
├── jobs/               后台任务和队列
├── runtime/            路径、进度和运行策略
├── web/                Flask 应用与 HTTP 路由
└── api/                对外结果序列化
```

新增识别阶段时，先在 `domain/stages.py` 注册阶段，再实现领域结果和阶段入口；新增 OCR 后端时，先在 provider registry 声明能力，再接入具体运行时。业务规则不应直接依赖模型名称，证据生成和最终判定应分开保存。

## Windows 桌面安装包

安装版的全部模型统一放在所选安装位置下的 `models/`。Paddle v6 检测和识别、印章专用模型、文字行方向、文档方向的 ONNX 与原生权重均位于 `models/official_models/`；字体、下载锁和临时缓存也使用同一根目录。启动器在启动识别服务前统一配置模型路径，继承的旧模型路径不会把安装版模型分散到其他位置。

旧版 AppData 中已下载的完整模型会在第一次加载模型时复制到新位置，已有目标模型优先，旧缓存保留；活动锁和临时下载文件不迁移。安装位置必须可写，不可写时会明确提示。运行数据库和回单文件仍保存在原有 AppData 数据目录；源码开发仍沿用现有模型路径规则。

Windows 用户使用 Tauri 桌面安装包。GitHub Actions 在 Windows 服务器上完成 Python/OCR 服务打包、Tauri 构建和 NSIS 安装包生成；推送 `v*` 标签后，安装包会作为 GitHub Release 附件发布，也可以在 Actions 页面手动运行工作流。

开发机可以在 `desktop/` 下执行：

```bash
cd desktop
pnpm install
pnpm tauri:dev:mac
```

Windows 本地构建脚本为 `desktop/scripts/build_installer.ps1`。它会先构建内部识别服务，再将服务作为桌面端资源打入 NSIS 安装包。用户只需要安装生成的桌面软件，窗口关闭时会同步结束本次启动的本地服务。
