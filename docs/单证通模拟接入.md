# 单证通真实接入

已切换生产环境，所有请求直连（requests.Session.trust_env=False），不使用环境代理。密钥只保存在 Git 忽略的 `config/danzhengtong.local.json`；`.env.example` 仅列配置项，应用不自动加载 `.env`。环境变量 `DZT_*` 优先于本机 JSON。

## 使用

重启应用并刷新页面，在识别配置中选“单证通”快捷方案。它启用印刷字段、签收填写、日期和印章文字；需要商品明细时另选本地商品识别。每张单据上传一次、提交一次，多个识别阶段共享同一结果。现有后台队列按张串行，接口模块也用锁防止同进程并行提交多张。

生产参数：

- 上传：`http://techfile.i.sinotrans.com:80/objectstorecloud/files/v2`
- 提交：`https://api.sinotrans.com/ocr/general-async/v1/extractGeneralDataAsync`
- 查询：`https://api.sinotrans.com/ocr/async/v1/getResultByReqUuid`
- `docType=SINGLE_LLM_EXTRACT_ASYNC`
- `modelId=logistics_samsung_deliverynote_1503`
- `sysCode=LOGISTICS_SAMSUNG`、`orgId=101517`
- 回调仍填写 `http://172.30.197.3:10000/OcrPlugins/customsOcr/testNotify`，但程序不等待回调。

## 查询与失败

提交返回 reqUuid 后，等待 2 秒查询；commitResult 为 null 或空对象时继续等待 2 秒再查询。取得非空的 data.commitResult 后映射字段，再处理下一张。HTTP 200 本身不代表识别完成。

结果等待上限为 60 秒，DZT_POLL_TIMEOUT_SECONDS 可设得更短，旧配置超过 60 秒时按 60 秒执行；查询请求的连接和读取超时也受剩余等待时间限制。暂停期间不再发起查询，已经发出的请求返回后进入暂停状态；继续时沿用当前 reqUuid，暂停和继续均不重置总等待时间。上传/提交/查询错误或轮询超时会显示失败，不使用模拟数据替代，也不在其他识别阶段重新上传。受理后的错误信息包含 reqUuid，可用于后续人工查询。超时仅停止本地等待，不能取消远端任务；同一进程的锁不覆盖额外启动的独立应用实例。

进程重启后的任务恢复仍由现有队列处理，目前没有把远端 reqUuid 单独持久化为可续查任务；应用正在识别时应避免重启，以免恢复任务重复提交。

## 字段映射

实际文本读取 `data.commitResult[字段名].value`，包括仓库联系人、接收人、合计/实收/拒收数量、客户名称、要求到货、签收日期、签章要求和收货客户印章。空值保留为空，数值 0 保留为字符串 "0"。

字段 ratio 原样保存在 provider_ratio，含义尚未确认，不直接当置信度。真实接口返回的签收日期与要求到货日期有效时直接比对，相同即为匹配，不再强制要求手动确认；日期依据注明“单证通”。空值、无效日期或缺少要求日期仍不能通过。

2026-09-11 起按当前业务要求，真实接口成功返回的字段暂按正确结果采纳，不再因“仅单证通识别，文档版式待复核”要求人工确认。保留原始字段、来源及 ratio，也不伪造文档分类或识别置信度。仅识别日期/印章、空字段、失败或模拟结果不适用；日期印章比对、未执行项目及实际发现的文档分流问题继续按原规则处理。

印章文字逐字比对签章要求，忽略空白及所有 `()（）`；错字或多字判不匹配，仅缺字判部分匹配。清瞳模板、清瞳 OCR、单证通文字三路中任一路完整匹配，客户印章即为匹配；主印章文字按匹配等级、要求文字覆盖率、文字相似度选择最佳来源。复核区保留各路文字和判定。模拟日期、印章结果继续保留模拟标记，不作为可靠判定。商品明细没有出现在当前场景返回中，不生成假商品行。

上传用 multipart 表单，org_id=101517，source_code 默认复用 LOGISTICS_SAMSUNG，可用 DZT_UPLOAD_SOURCE_CODE 覆盖；file_type 为文件后缀，file_is_outer_visible=N。上传请求不带识别凭证。优先读取响应 fileId，兼容字符串 data；不保存带下载签名的 filePath。

模拟代码只用于显式 mode=mock 的离线测试，默认和当前本机配置均为 real。历史模拟结果保留模拟标记，真实失败不会回退模拟。
