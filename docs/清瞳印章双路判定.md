# 印章三路文字判定

清瞳模板名称 `matched_seal.label`、清瞳 OCR 文字 `text_formatted` 和单证通印章文字分别对照本单签章要求。任意一路完整匹配，即将客户印章判为匹配；其余结果的错字、漏字或接口失败不能否决已取得的完整匹配。
| 每一路文字与签章要求的关系 | 该路结论 |
| --- | --- |
| 完全一致 | 匹配 |
| 仅缺字，已识别字仍按原顺序出现 | 部分匹配 |
| 存在错字、多字或顺序差异 | 不匹配 |
| 没有文字、缺少要求或接口失败 | 未识别／无法判断／识别失败 |

比对时删除所有空白及 `()（）`，并统一全半角 ASCII 字符；不纠正真实错字。例如“太原市伊加壹电子服务总汇”与“太原市伊服壹电子服务总汇”不匹配。接口的 `matched_seal.similarity` 和 `text_similarity` 仅保留为证据，不设匹配门槛。

“识别印章”展示最匹配的一路原文，先比较匹配等级（匹配、部分匹配、不匹配），再比较按顺序覆盖的要求文字比例，最后比较文字相似度。即使一段长文字因多字仍为不匹配，只要覆盖了更多要求文字，也可比残缺的错字结果更适合展示。各路原文和独立状态保留在识别依据中，不拼接不同结果。

没有完整匹配时，存在仅缺字结果则为部分匹配，仍需人工核对；全无完整证据时不作可靠否定。参考章不增加第四路投票。模拟结果不用于可靠判定。其他字段、日期和文档类型的复核条件独立生效，人工确认继续保留。

复核区分开展示清瞳模板名称、清瞳 OCR 文字、单证通印章文字、框内本地文字及各自是否匹配；列表、筛选及导出支持“部分匹配”。新识别和重新识别使用新规则。已有结果可用 `tools/refresh_provider_results.py --ids 记录编号` 预览规则更新，加 `--apply` 保存；使用已保存的接口原文，保留原始识别快照并记录变更，跳过人工处理过的记录。

相关测试覆盖逐字比对、三路任一路匹配、仅缺字、空格和括号、模板文字胜出、单证通文字胜出、接口失败不否决其他完整匹配、原始证据保留、已有结果刷新与人工复核保护。

## 印章区域来自清瞳，不再自己检测（2026-09-18）

清瞳响应里每枚印章都带 `xyxy` 像素框，那就是接口真正读过、并据此给出文字与匹配结论的那块像素。本地不再围着签署区自行猜测印章位置：

- 「本地 + 清瞳印章 API」：本地识别直接用清瞳的框裁图与识别，`detect_seal_regions` 只在清瞳没有返回可用框时兜底。两路证据从此描述同一枚印章，而不是各说各话的两枚。
- 「仅清瞳印章 API」：本模式按定义不跑本地识别，但清瞳的框仍会落成 `seal_check.regions` 并裁出 `processing_artifacts.seals`（此前这两个字段恒为空，审阅页印章产物标签一直显示“没有保存的中间处理图”）。裁剪图不带任何衍生图，附 `source=清瞳印章区域` 与 `api_index` 便于回溯。
- `商品付讫章` 由 `compare_qingtong_seal` 前置排除，因此这里的框必定是可能承载客户印章的那几枚。

区域用页面分数表达（`SealRegion`），换算自原图像素；裁剪证据图直接按像素框写盘，避免分数往返造成角点偏移。`api_index` 保留接口响应内的原始序号，而展示用的 `index` 只数保留下来的框，避免删掉一枚付讫章后审阅页把唯一的客户章编号成“收货印章 2”。

实测存量 365 条带清瞳框的记录全部解出区域；对 `7330644044.jpg` 的框 `[1437,2906,2180,3521]` 裁出 743×615 的矩形「收货专用章」，印章墨迹占比 15.0%，位置与角色均正确。

## 框内本地通道可以投票（2026-09-18 策略变更）

原先的规则是「本地 OCR 不增加第四路投票」。这条规则的理由是：本地印章结果来自**自己围着签署区猜出来的**位置，比接口直接读整页的证据弱，让模糊/几何结果去否决接口判定不划算。

本地改成**直接复用清瞳返回的印章框**之后，这条理由就不再成立——它读的是接口自己判定时用的那同一块像素，是完全同质的证据。因此：

| 本地那一路的情况 | 是否投票 |
| --- | --- |
| 未打「清瞳印章区域」标记（自己检测的框） | 否，仍是旁证 |
| 标记为清瞳框，但结果是部分匹配 / 不匹配 / 无法判断 | 否 |
| 标记为清瞳框，且完整匹配 + 可靠 + 非模拟 | **是** |
| `seal_match_mode = all` | 否（仅记录） |

- `any` 模式下，框内本地完整匹配与接口两路同等有效，可把接口的「不匹配」改判为「匹配」；`seal_check.source` 显示为 `本地识别（清瞳印章区域）`，`recognized` 展示本地那一路原文，接口原文仍留在 `all_recognized` / `local_channel` 里。
- `all` 模式下本地通道**只记录不判定**：该模式问的是「接口每一路是否都一致」，本地重读无法让一个已经不一致的接口通道变得一致，把它计入只会让原先通过的记录变成人工复核。
- 记录位置：`seal_check.local_channel`（该路全文与状态）、`seal_check.local_evidence`（双路模式下的本地结论）、`seal_check.region_source`（是否为清瞳框）。
- 两处合流点共用同一实现 `receipt_ocr/seal_local_channel.py`：双路模式在 `stage_seal` 合流，web 路径（本地引擎与清瞳同时勾选）在 `recognition_config.run_configured` 合流。web 路径下清瞳的预取响应会同时交给本地那一路，本地因此不必再自行检测印章位置。
