# 单证通真实接入

已切换生产环境，所有请求直连（requests.Session.trust_env=False），不使用环境代理。软件设置保存的配置优先于环境变量 `DZT_*`，环境变量优先于 Git 忽略的 `config/danzhengtong.local.json`。`.env.example` 仅列配置项，应用不自动加载 `.env`。密钥不在页面或识别证据中回显。

## 使用

重启应用并刷新页面，在识别配置中选“单证通”快捷方案。它启用印刷字段、签收填写、日期和印章；需要商品明细时另选本地商品识别。整页上传、提交一次，字段、签收填写和日期共享该结果；印章使用独立场景，每个完整印章子图分别提交。整页与印章分别调度，印章准备或整页提交失败不会停止另一场景；已有请求编号只续查，提交状态不明的请求不会自动重发。后台常规识别与单证通各自执行、保存；单证通等待结果不占用常规识别线程，也不持有 HTTP 请求锁。实际提交和查询在同进程内逐次发出，服务端处理和请求间的等待可重叠。时间轴分别显示“单证通整页”和“单证通印章”。

“设置 → 单证通配置 → 高级配置”分别保存整页场景 ID 和印章场景 ID。旧配置缺少 `seal_model_id` 时自动采用默认印章场景；也可用 `DZT_SEAL_MODEL_ID` 配置。设置内的“整页连通测试”只验证整页场景，印章场景在正式印章识别时独立调用。

生产参数：

- 上传：`http://techfile.i.sinotrans.com:80/objectstorecloud/files/v2`
- 提交：`https://api.sinotrans.com/ocr/general-async/v1/extractGeneralDataAsync`
- 查询：`https://api.sinotrans.com/ocr/async/v1/getResultByReqUuid`
- `docType=SINGLE_LLM_EXTRACT_ASYNC`
- 整页 `modelId=logistics_samsung_deliverynote_1503`（`model_id` / `DZT_MODEL_ID`）
- 印章 `modelId=logistics_samsung_outseal_1503`（`seal_model_id` / `DZT_SEAL_MODEL_ID`）
- `sysCode=LOGISTICS_SAMSUNG`、`orgId=101517`
- 回调仍填写 `http://172.30.197.3:10000/OcrPlugins/customsOcr/testNotify`，但程序不等待回调。

## 查询与失败

自 2026-11-02 起，网页后台任务使用独立的 `danzhengtong_jobs` 表和工作线程。提交返回 `reqUuid` 后立即持久化，再安排查询。`commitResult` 为 null 或空对象时保持“等待结果”；HTTP 200 本身不代表识别完成。前 60 秒每 2 秒查询，1～10 分钟每 30 秒查询，10 分钟后每 120 秒查询。单次 GET 的连接／读取超时分别为 5／15 秒；网络错误保留原请求、至少等待 30 秒后续查。

回单管理使用一个“开始运行”入口，按设置启动已启用的来源，未启用单证通时不额外提交。常规识别的完成进度与单证通独立；单证通等待不计入常规处理中。已有结果满足当前通过条件时可先通过；未满足时标记“待结果”，全部匹配或必须单证通匹配的规则会继续等待。列表每行保留“查看”和更多菜单，单证通查询放在任务区及更多菜单中；这些查询只按原编号 GET，不上传、不重新提交。常规暂停、单证通新提交暂停和自动查询开关分别控制；关闭自动查询后仍可手动查询。关闭浏览器不影响后台；退出软件期间停止查询，重启后续查。服务端结果有效期仍由服务方决定。

取回原始响应后先保存，再基于已保存的各路证据重新选择字段及比对日期／印章，不再次运行本地 OCR 或清瞳。人工修改、较新识别或图片版本变化时保留返回结果供查看，不覆盖当前记录。普通常规重试继承原请求；只有明确的“重新提交单证通”建立新请求。任务表保存接口环境和账号指纹，不保存凭证。

提交明确被拒绝时显示“处理失败”；提交响应丢失或提交途中进程退出、尚未取得编号时显示“提交状态待确认”，不自动重发。历史记录缺少可组合的识别证据时，取回结果供人工核对。新版之前只有错误文本中编号的旧超时项不会自动猜测关联。

旧同步 API／直接调用 `Client.recognize()` 保持原有最多 60 秒等待行为，`DZT_POLL_TIMEOUT_SECONDS` 仍只控制这条同步路径；网页后台已不受这一总等待上限限制。

## 字段映射

实际文本读取 `data.commitResult[字段名].value`。整页场景提供仓库联系人、接收人、合计/实收/拒收数量、客户名称、要求到货、签收日期和签章要求。印章场景提供 `收货客户印章`、`印章颜色`、`印章类型`。空值保留为空，数值 0 保留为字符串 "0"。

印章上传前排除已定位为发货单位的章。对于旧位置规则可能保留的左下方章，只有同页脚区域还存在右侧客户章，且左侧章边框可靠拟合为明显的横向椭圆时，才进一步排除；独立左下章、圆章及几何证据不确定的候选继续保留。该筛选不额外执行文字 OCR 或远程识别。已准备但尚未受理的历史发货章同样跳过，已取得受理编号的请求继续按原编号查询。

印章上传使用章色分离增强后的完整子图，保留原始方向，不执行本地旋正、环字展开或分区读取。接口负责旋正；返回结果中的 `data.imgUrls` 用作旋正图来源，下载成功后复核直接使用接口返回的图片。后台队列先保存文字、颜色和类型，再独立下载旋正图；下载失败不会阻塞结果保存或下一次识别。时间轴分别记录返回后等待、结果合并保存和旋正图下载，旧记录没有分段时间时标注“未细分”。字段、日期仍使用整页场景。

“设置 → 单证通配置 → 下载单证通旋正图”默认开启，也可用 `DZT_DOWNLOAD_SEAL_IMAGES=false` 关闭（软件内已保存的配置优先）。关闭后不发起旋正图下载，排队中的下载同样跳过，已有缓存仍可查看；识别文字、颜色和类型照常保存。开启时，返回地址无法访问会保留文字并提示图片下载失败，不把本地图片标成服务端旋正图。各路本地和清瞳的图片处理方式不受此开关影响。

字段 ratio 原样保存在 provider_ratio，含义尚未确认，不直接当置信度。真实接口返回的签收日期与要求到货日期有效时直接比对，相同即为匹配，不再强制要求手动确认；日期依据注明“单证通”。空值、无效日期或缺少要求日期仍不能通过。

2026-09-11 起按当前业务要求，真实接口成功返回的字段暂按正确结果采纳，不再因“仅单证通识别，文档版式待复核”要求人工确认。保留原始字段、来源及 ratio，也不伪造文档分类或识别置信度。仅识别日期/印章、空字段、失败或模拟结果不适用；日期印章比对、未执行项目及实际发现的文档分流问题继续按原规则处理。

印章文字逐字比对签章要求，忽略空白及所有 `()（）`；错字或多字判不匹配，仅缺字判部分匹配。清瞳模板、清瞳 OCR、单证通文字三路中任一路完整匹配，客户印章即为匹配；主印章文字按匹配等级、要求文字覆盖率、文字相似度选择最佳来源。复核区保留各路文字和判定。模拟日期、印章结果继续保留模拟标记，不作为可靠判定。商品明细没有出现在当前场景返回中，不生成假商品行。

上传用 multipart 表单，org_id=101517，source_code 默认复用 LOGISTICS_SAMSUNG，可用 DZT_UPLOAD_SOURCE_CODE 覆盖；file_type 为文件后缀，file_is_outer_visible=N。上传请求不带识别凭证。优先读取响应 fileId，兼容字符串 data；不保存带下载签名的 filePath。

客户端仅保留真实接口流程，已移除模拟模式和模拟样例文件。旧配置中的 mode=mock 或 DZT_MODE=mock 会明确报错，避免意外发送真实请求；不再需要配置 mode。离线测试通过注入 HTTP 响应验证真实流程。历史模拟结果仍保留模拟标记，不用于可靠判定。

测试：`python -m pytest tests/test_danzhengtong.py tests/test_danzhengtong_live.py tests/test_danzhengtong_jobs.py tests/test_danzhengtong_frontend.py tests/test_job_queue.py -q`。异步测试注入传输响应，不调用真实服务；覆盖重启续查、两路独立完成、暂停期间仅单证通完成、数据库繁忙时不重发、普通重试转交原请求、人工修改及图片版本保护。
