# 九项字段与识别归属

本次将业务输出收敛为九项。商品明细表和客户印章核验仍保留各自开关。

|归属|字段|当前处理|
|---|---|---|
|印刷字段|仓库联系人、合计数量、客户名称、要求到货、签章要求|复用整页 OCR；联系人从发货单位上方读取，合计只读取合计行的数量列|
|手写签名|仓库接收人|独立可选阶段，默认关闭；仅收集明确签名标签旁的文字候选，需人工确认，不从客户名或备注猜测姓名|
|签收日期|签收日期|沿用独立日期识别及核验，输出与 date_check.actual 同步|
|单证通预留|拒收数量、实收数量|本地不识别、不推算、不把空白变成零；等待单证通接入|

## 输出、复核和兼容

- fields 固定为用户指定顺序的九项，空值保留为空字符串；复核界面按来源分组，Excel 使用同样的字段范围。
- 商品明细继续保存在 product_table。商品明细原文不再混入业务字段列表。
- 历史结果的复核界面同样只展示指定字段；不批量改写历史数据库和人工真值文件。
- 制单日期、运单号等仍供日期业务检查和重新识别使用，保存在 internal_fields，不作为待填写业务字段，也不因这些旧字段的识别置信度降低而新增字段复核要求。
- 新格式保存人工真值时，不要求已移除字段、空签名、预留数量或关闭的商品明细。已有人工真值仍保留；对新格式结果的字段准确率只统计当前九项中已有真值的字段。
- 单证通目前仍显示待接入。此次未启用接口，也未改变日期补全、年份推断或最终日期/印章判定规则。

## 验证

完整回归 578 项通过。新增覆盖输出范围、日期同步、内部比对信息保留、联系人与接收人分离、合计列定位，以及存在清楚的实收/拒收文字时仍不做本地提取。实际生成 Excel 并核对九项业务表头、数量空白、日期类型、统计公式和百分比列；使用临时数据库检查浏览器界面。

字段缩减减少需要展示和复核的信息；本地引擎目前仍识别整页文字，不据此承诺 OCR 推理耗时明显下降。
