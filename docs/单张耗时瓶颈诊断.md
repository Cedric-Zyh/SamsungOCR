# 印章识别链路说明

这份说明记录当前印章识别结构和耗时观察，旧的专用模型分支已经移除。

## 入口和阶段

印章本地识别由 `receipt_ocr/recognition/seal/pipeline.py` 编排，固定经过三段：

```text
SealRegion
  -> preprocess.regions / preprocess.shapes
  -> ocr.interface / ocr.region
  -> postprocess.regions / postprocess.decision
```

每个印章先由 `preprocess.shapes.classify_shape()` 归为矩形、椭圆或圆形。形状只决定要生成哪些图片变体：

- 矩形：章色隔离图、方向校正图、编号行图；
- 椭圆：方向校正、拉伸归一化、章型横向分带、环形展开；
- 圆形：方向校正、章型横向分带、环形展开及必要的旋转对照。

预处理阶段只调用共享 OCR 接口获取必要的方向提示，不直接依赖具体引擎；所有最终变体都通过 `ocr.interface.OcrReader` 读取，统一转换为 `OcrRead`。结果处理阶段负责去重、同章片段聚合、冲突保护、候选排序和最终印章判断。

## 模块职责

| 目录 | 职责 |
| --- | --- |
| `preprocess/` | 形状判断、裁剪、颜色隔离、旋正、椭圆归一化、环形展开 |
| `ocr/interface.py` | 唯一 OCR 适配入口，屏蔽具体提供方调用方式 |
| `ocr/region.py` | 读取主流程和可选补充流程生成的图片变体 |
| `ocr/read_policy.py` | 根据要求文本和置信度决定是否需要补充读取 |
| `ocr/secondary.py` | 读取补充变体并保留来源、置信度和使用原因 |
| `postprocess/` | 聚合文本、重建可验证片段、生成结果和 artifact |
| `contracts.py` | `PreparedSeal`、`OcrRead`、`SealResult` 等跨阶段数据契约 |
| `providers/` | 清瞳等外部印章区域服务适配器 |
| `reference/` | 已知印章参考图的几何和章色复核 |

## 补充识别配置

补充识别使用 `SEAL_SECONDARY_READ_MODE`：

| 值 | 行为 |
| --- | --- |
| `auto` | 只有补充提供方已获授权且与主读取不同才执行 |
| `local` | 对远程主读取启用本地 v6 补充读取 |
| `off` | 跳过补充读取，并在 artifact 中记录原因 |

补充读取只能消费预处理阶段已经生成的图片，不能重新裁剪或绕过统一 OCR 接口。结果字段使用 `secondary_read_*`、`robust_line_*` 等 provider-neutral 名称。

## 维护规则

新增印章形状时，只在 `preprocess/` 增加形状策略，并让它输出 `PreparedSeal`；不要在 OCR 或业务判断中增加形状分支。新增 OCR 引擎时，只实现 `OcrReader` 的提供方适配；不要在 `pipeline.py` 中直接调用模型。新的匹配规则放在 `postprocess/`，并通过 `SealResult` 或 artifact 对外暴露证据。
