## 阶段与验收

1. 判定规则：机器比较与人工确认分离；首次识别、异步重算和历史刷新使用一致的比较策略。
2. 保存证据：集中整页／独立印章来源选择及旧格式适配；失败或未完成的独立印章证据不可借用整页成功记录。
3. 远程任务：纯状态转换与事务分离；新任务记录运行归属和复用来源，旧数据保持兼容；保留未知提交不重发、UUID 优先及手动查询边界。
4. 正式运行时：明确资源所有者和幂等启动／关闭，重试公共流程下沉；保持 HTTP 接口及现有脚本入口兼容。
5. 数据库：版本化迁移、原子升级与触发器更新；区分结构升级、旧数据兼容修复和启动恢复；不操作真实业务数据库。
6. 前端：导入完成通知由页面协调层处理；复核返回路由、焦点、滚动和标签由弹窗宿主统一管理。
7. 集成：针对性回归、交叉复审、完整 Python／Node 测试、依赖边界与差异检查。

## 已完成的结构调整

- 机器判定：`domain/check_comparison.py` 定义基础比较规则；`application/saved_checks.py` 统一保存证据重算；机器快照回放不再调用人工复核私有函数。人工确认与修改仍由 `review.py` 负责。
- 证据读取：`domain/saved_evidence.py` 统一 `details/result` 与 typed Mapping；独立印章显式空／失败来源不可借整页成功。普通整页空占位继续保留旧回退行为。
- 远程任务：`domain/remote_tasks.py` 集中纯状态规则；`domain/remote_runs.py` 明确任务所属本地运行及复用来源。新的 `run_link` 写入原兼容 JSON，迟到的网络回写不能覆盖更新后的运行关联。持久化分为取数、纯投影和旧数据兼容推断。
- 正式运行时：`web/runtime.py` 拥有识别资源、队列、初始化、维护与关闭。重复启动不会重复恢复或创建 worker；停止超时保留所有权，覆盖本地、远程与图片线程；关闭期 HTTP 返回 503。保留既有 Web 模块别名和脚本入口，不实施整个 Flask 多实例工厂改写。
- 重试服务：`application/retries.py` 共用单条／批量准备、识别与整批入队校验；HTTP 保持原错误状态码和同步／后台模式回退。
- 数据库迁移：`persistence/migrations.py` 提供组件顺序版本与事务记录；receipt / local queue / remote queue 各自拥有迁移，持久化层不反向依赖 jobs。旧摘要和调度触发器会被替换并重建派生值。历史导入格式修复和运行恢复保持独立。
- 前端：导入发送完成事件，工作台命令接管日期和筛选；`shell/review_dialog.mjs` 统一复核返回路由、焦点、滚动及标签，review 保留编辑和请求清理。

## 交叉复审修正

- 保留旧整页空占位的来源回退，不把独立印章的禁止回退规则扩大到旧整页格式。
- 第一次全量在 2964 项通过后发现真实历史样单投影兼容问题：旧 `assembly` 给每个变体投影 `danzhengtong_seal: null`，即使文档从未执行独立章识别。仅对变体 `details` 的 null 占位恢复回退；文档顶层显式 None、独立章 {}／失败及独立模型缺 trace 仍禁止借用整页来源。旧 fixture 保持原样，并新增持久化负例。
- 关闭超时后旧识别线程可能继续提交结果：只有线程全部退出才标记关闭，未退出禁止替换 owner 和接纳新任务。
- 真实线程启动失败可能留下尚未启动的 Thread：停止时仅 join 存活线程，避免清理错误掩盖原始失败。
