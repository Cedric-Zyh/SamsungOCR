# 代码审查修复（2026-09-10）

本次修复基于现有工作区继续进行，没有重跑业务样单或改写业务识别结果、人工真值。

## 核验与复核

- 残缺日期优先保留图片中明确出现的月份；异月不能补成要求到货的月份。非法月份不回填。
- 日期要求为空时，不再因两个空值相等而跳过下方裁剪；未知文档类型可由后续已授权模型的可靠证据恢复。
- `OCR_BACKEND=auto` 正常进入自动检测。
- 人工复核规则集中到 `receipt_ocr/review.py`。只保存备注或回传未改动字段时保留原日期、印章可信度；日期修改或 `actual_date_confirmed=true` 才确认日期，印章沿用独立确认。
- 页面提交 `review_revision`。单笔保存使用事务锁并检查完整逻辑回单版本，陈旧表单返回 HTTP 409、`code=review_revision_conflict`，不覆盖服务器结果；前端保留未保存编辑。未携带版本的旧接口调用保持兼容。
- 多页逻辑回单携带各物理页的证据版本；即使人工覆盖显示了旧合并值，续页更新也使旧表单失效。

## 多页回单、查询与队列

- 单笔与批量复核共用覆盖写入逻辑，物理页明细不写入合并后的续页内容；批量操作在同一事务提交或回滚。
- 重新识别后解除失效关联；删除前校准旧关联，避免删除已独立的记录。
- 队列冲突检测忽略派生分页关系，保留对实际业务修改的检测，并兼容安全升级旧排队版本。
- 新增 `Database.query_receipts()`：完整合并、筛选、计算总数后再分页。按订单号、客户或续页文件名筛选不会丢续页。
- `/api/results`、`/api/history`、`/api/daily-results` 显式接收 `page`、`page_size` 时返回 `items/total/page/page_size`；旧调用保留数组响应。
- `reviewable=1` 在分页前排除识别失败、错误记录和正在识别的关联页。按日期的复核保留跨日重试口径。
- 新增文件基名索引，初始化时自动补齐旧记录。每次处理仅重算相关页组，跳过未变化的关系写入。

## 前端与评测

- 修复 HTML 属性转义，保留引号文字并防止生成事件属性。
- 记录页和复核队列支持真实分页；后台刷新保留当前页有效选择，异步详情切换不丢弃等待期间的新编辑。
- 根据活跃页面轮询，隐藏标签暂停；统计请求合并并降低刷新频率。
- 统计增加 `field_coverage`，明确已评字段、独立日期评测和缺真值字段。旧 301 张真值没有被补成未经核对的新字段标注。
