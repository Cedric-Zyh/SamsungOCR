## 解析

`receipt_ocr/parser.py` 保留原名称的显式导出，具体实现分别位于：

- `parsing_text.py`、`parsing_constants.py`：文本规范化与原有常量、业务主数据。
- `parsing_fields.py`：字段提取、纠错调度和字段可信度。
- `field_identity.py`、`field_requirements.py`：客户身份、地址、签章要求等顺序纠错规则。
- `parsing_products.py`：商品表格解析。
- `parsing_dates.py`：日期解析与比较。
- `parsing_seals.py`：印章文本匹配。

原 814 行的 `repair_contextual_fields` 拆为 11 组有明确参数的规则，入口按原顺序调用。已有 `field_rules.py`、`product_rules.py`、`seal_rules.py` 继续使用兼容入口，无需同步迁移所有调用方。

## 日期

`date_crops.py` 负责临时目录生命周期和识别步骤调度；`date_crop_state.py` 明确区分一次识别、单个裁剪区域和槽位识别所需的状态，OCR 依赖由入口显式传入。

- `date_crop_workflow.py`、`date_crop_preparation.py`、`date_crop_regions.py`、`date_crop_region_output.py`：裁剪、常规识别和证据输出。
- `date_crop_confirmation.py`、`date_crop_color_confirmation.py`：跨模型、跨区域等补充确认。
- `date_crop_audits.py`、`date_crop_line_audits.py`、`date_crop_final_audits.py`：低置信度及后续补充识别。
- `date_crop_slot_collection.py`、`date_crop_slot_selection.py`、`date_crop_slot_output.py`：日期槽位采集、选择和记录。

`date_evidence.py` 保留旧导出，底层按日期片段、图像处理、槽位识别、完整日期一致性、业务日期规则、槽位证据和审计证据拆分。

`stage_date.py` 负责文档类型分流、规则调用和输出，日期选择位于 `date_selection.py`，可信度与复核限制位于 `date_confidence_rules.py`，明确状态位于 `date_decision.py`。

日期判断的规则优先级、提前结束条件、补充模型范围以及仅供人工查看的证据限制均保留。

## 印章识别

`seal_crops.py` 负责临时目录、章区遍历和补充识别的调度，原 1105 行函数缩为 58 行。步骤按原顺序拆入：

- `seal_crop_regular.py`：常规模型、第二模型的章区识别和证据记录。
- `seal_crop_mobile.py`：Mobile 分带识别对公司文本冲突的复查。
- `seal_crop_routes.py`：是否启动 Server 补充识别、候选排序和数量限制。
- `seal_crop_audit_images.py`：补充识别所需的图像和分带准备。
- `seal_crop_audit.py`：读取、重组、记录和合并重叠章区证据。
- `seal_crop_types.py`：请求、章区证据、路由和补充识别的明确状态。

测试中的旧 OCR 替身只调整到新的实际消费模块，保留原输入和断言。

## 印章参考匹配

`seal_reference.py` 保留参考样本管理和 `SealReferenceMatcher` 入口，并显式导出已有规则函数、常量。实现拆为：

- `seal_reference_geometry.py`：OpenCV 实例、图像表示、缓存、局部特征与颜色比较。
- `seal_reference_constants.py`：原校准阈值及供结果展示的阈值说明。
- `seal_reference_gates.py`：单条证据的匹配条件和排序。
- `seal_reference_consensus.py`：独立参考文件之间的一致性判断。
- `seal_reference_decision.py`：按原优先级选择匹配路径并组装结果。
- `seal_reference_confidence.py`：各匹配路径的可信度计算与上限。

## 前端

`static/app.js` 仅加载并初始化应用。`static/modules/application.mjs` 显式组装控制器、安排初始化和轮询，各控制器通过参数和回调连接。

模块分别管理导入、识别设置、记录列表、复核编辑、复核证据、复核队列、工作台、统计和导航。`state.mjs` 按业务区域划分状态，`api.mjs` 与 `ui.mjs` 承接公共能力。

拆分保留分页与选中项、未保存编辑保护、复核版本检查、异步请求先后顺序保护、后台刷新策略和 HTML 转义。行为测试直接加载实际前端模块，不再从源码中截取函数。

## 维护约定

- 修改规则时定位到对应实现模块；兼容入口只负责导出或调度。
- 顺序规则的前后位置属于业务行为，不能为了整理代码随意交换。
- 新增跨步骤状态需声明明确字段，不通过动态变量转发隐藏依赖。
- 拆分本身不代表 OCR 模型推理会更快，性能改动应另行测量。
