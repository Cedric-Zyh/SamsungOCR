# 识别性能与结构改造：第一轮

日期：2026-09-09

## 本轮交付

- 同一张图、同一实际 OCR 引擎的整页结果，在本次识别内共享。字段、商品、日期及本地印章无需各自重新识别整页。不同引擎分别执行，重试创建新缓存；局部裁剪与不同参数的识别不使用该缓存。
- 自定义方案的预览在各阶段合并后生成一次，合并日期框与主印章结果的区域，避免后续阶段覆盖前面阶段的标注。
- 自定义方案同时选择本地识别和清瞳时，清瞳请求与本地计算重叠执行。请求仅发送一次，印章比较仍使用字段阶段生成的签章要求。未选择清瞳时不发起请求；仅清瞳时沿用直接调用。
- 最终判定提取到 `receipt_ocr/decision.py`，供原识别流程、自定义方案、参考章匹配及人工修改后的判断共同使用。未知状态和不可靠证据保持待复核，字段阶段的关键复核原因传递到合并结果。
- 执行上下文和性能计数独立放在 `receipt_ocr/execution.py`，通过请求内上下文隔离不同图片。远程请求只并行执行网络操作，Paddle 原有的预测锁保留。
- 导入 `app` 不再自动初始化数据库或回收任务。直接启动时显式初始化，Flask CLI / WSGI 在首次请求时初始化。测试使用临时数据库、真值文件和证据目录。

## 耗时记录

返回结果新增 `processing_timings`，随现有结果 JSON 保存，不需要数据库迁移。历史记录没有该字段。

`processing_timings.steps` 中每项包含调用次数 `calls` 和秒数 `seconds`：

| 字段 | 含义 |
|---|---|
| `stage.fields.*`、`stage.products.*`、`stage.date.*`、`stage.seal.*` | 自定义方案各阶段与引擎的耗时，包括其内部调用 |
| `page_ocr` | 实际执行的整页 OCR，包含模型等待和加载 |
| `paddle_queue_wait` | 获取 Paddle 预测锁的等待 |
| `paddle_model_setup` | 获取或首次创建整页／文字行模型 |
| `paddle_text_inference` | Paddle 检测与文字识别的实际预测 |
| `paddle_line_inference` | Paddle 文字行预测 |
| `vision_ocr` | Vision 文字识别 |
| `qr_decode` | 二维码解码 |
| `date_recognition` | 日期局部识别整体，包括裁剪和补识别 |
| `date_crop_generation` | 基础日期区域裁剪与清理，不包含所有后续衍生图 |
| `local_seal_recognition` | 本地印章识别 |
| `seal_api` | 清瞳客户端调用，包括上传及接口等待 |
| `preview_generation` | 最终标注预览生成 |

`page_ocr_cache_hits` 是整页结果复用次数。`processing_seconds` 继续表示识别流程的实际经过时间。

这些计时存在父子包含关系；清瞳还可能与本地阶段重叠，因此不能把各项秒数直接相加。模型排队时间包含在所处阶段耗时中。总耗时不包含图片上传至本地服务前的时间、数据库保存及随后页面刷新。

## 本地样单对照

使用本轮修改前保存的源码快照与修改后的流程，读取已有记录 #1596、#1594 的原图和方案。两版共享已预热的 Paddle Mobile 模型，执行顺序交替；清瞳使用各样单已保存的接口响应，没有重新上传图片，也没有写业务数据库。

| 样单 | 日期区域数 | 修改前 | 修改后 | 减少 |
|---|---:|---:|---:|---:|
| #1596 | 5 | 41.52 秒 | 24.43 秒 | 41.2% |
| #1594 | 2 | 37.29 秒 | 21.40 秒 | 42.6% |

两张图的字段、字段置信度、商品结果、日期核验、印章核验、整体结论及复核状态均一致；复核原因增加了相应阶段的说明。修改后整页 OCR 各执行一次，命中复用一次；日期原有区域和补识别保留。

单次整页 OCR 分别耗时 17.34 秒、16.56 秒，日期局部流程分别耗时 6.55 秒、4.28 秒。该对照说明重复整页识别是这两张图的重要瓶颈。它不是整个样单集的性能结论，也不代表包含真实清瞳等待、首次模型启动和批量竞争时的总耗时。清瞳与本地计算重叠的行为另由同步事件测试验证，不把它计入上述提速。

## 验证范围

定向测试覆盖：整页复用、不同引擎与不同图片隔离、失败后重试、并发任务上下文隔离、权限检查、一次预览保留两类标注、统一判定、复核原因传递、清瞳请求与本地阶段重叠且只调用一次、清瞳失败仍保留字段、Paddle 异常释放锁，以及导入应用不访问数据库。

原有识别规则、复核、分页、数据库、评测与图像处理测试继续作为回归基线。

本轮全量验证结果：526 项测试通过，耗时 69.91 秒；输出 10 条第三方依赖提示。新增及相关定向测试 25 项通过。差异空白检查通过。

## 后续范围

本轮没有修改日期提前结束条件或降低识别阈值。应先积累真实耗时，再针对缺失、模糊、不匹配和跨年日期分别验证分级补识别策略。

持久化逐文件任务队列、独立回单身份、SQL 层筛选分页、评测真值与参考库版本隔离，以及完整应用工厂仍需后续实施。首次初始化仍沿用原有单进程任务回收方式，本轮不宣称已经支持多个服务进程。

已有服务进程需要重启后才会加载新代码。重启应放在当前批次完成之后，避免中断正在识别的任务。
